# 0001. Форк живёт без апстрима

Статус: принято.

## Контекст

Форку нужны доработки (закрытый вход, Бессрочная подписка, чеки «Мой налог»),
которые автору не подходят. На сервере должен стоять известный образ, который
`/update` автора не затрёт.

## Решение

- PR автору не отправляем. Доработки живут в ветке `fus1ond` — она ветка по
  умолчанию.
- `main` только зеркалит автора. Релизы автора вливаются в `fus1ond`
  merge-коммитом от тега автора, без rebase: в истории видно, что пришло и где
  был конфликт.
- Свой образ `ghcr.io/fus1ond/chill-remna-bot` собирает CI форка по тегу
  `v<версия автора>-f<N>` плюс тег sha, только linux/amd64, без `latest`.
  Пуш в ветки образ не публикует.
- Авторские тесты и линтеры гоняются на нашей ветке без изменений. Авторская
  сборка образа и публикация сайта документации в форке отключены в настройках
  Actions (`gh workflow disable`), а на `fus1ond` ещё и условием на владельца
  репозитория.
- На сервере compose закрепляет конкретный тег, без docker.sock и без
  `pull_policy: always`.

## Последствия

- Каждый релиз автора — ручное слияние с разрешением конфликтов.
- Авторские файлы воркфлоу в форке держат условие на владельца
  репозитория; при слиянии его легко потерять — проверять. Главная защита —
  отключение в настройках, оно слиянием не теряется.
- Каналы обновления автора (`latest`, `dev`, `/update` из бота) в форке не
  работают.

Как это делать руками — [docs/fork.md](../fork.md).
